# Deploy the Bellwether preview from iPhone Safari

The environment network rules now work. The exact remaining restriction is GitHub's credential: `POST https://api.github.com/user/repos` returns **HTTP403, `Resource not accessible by integration`**. The integration can read the source repository and its Pages settings, but it cannot create this new account repository. No further network change is needed for that restriction. The separate preview repository currently returns404 and its expected public URL is not live.

You can complete this alternative entirely in Safari while signed into GitHub. It needs no installation, paid hosting account or personal access token.

1. [Create the separate preview repository](https://github.com/new?name=shattered-reef-bellwether-preview&visibility=public). Use the exact name **shattered-reef-bellwether-preview**, select **Public**, and turn on **Add a README file**. Leave your existing `shattered-reef` repository alone.
2. In the new repository, [open Pages settings](https://github.com/f2456hhchv-bit/shattered-reef-bellwether-preview/settings/pages). Under **Build and deployment → Source**, select **GitHub Actions**.

4. [Open the new repository's Actions tab](https://github.com/f2456hhchv-bit/shattered-reef-bellwether-preview/actions). Wait for **Bellwether redesign preview** to turn green. If it has not started, select the workflow and use **Run workflow**.
5. Open the URL shown by the successful **github-pages** deployment. The expected address is `https://f2456hhchv-bit.github.io/shattered-reef-bellwether-preview/`. A green run includes actual HTTP checks of its title and `preview.json`; tell Codex when it is green so the public game can also receive the full browser check. This document does not claim that the address is already live.

**Why this does not affect production:** the workflow runs only in the specifically named new preview repository and uses that repository's built-in GitHub token to deploy its own Pages site. It reads the public `design/bellwether-phase2` source branch with credential persistence disabled. It never merges, pushes to, configures, or deploys the original repository. The new repository's default branch is named main; this is separate from the original game's main, which stays unchanged. Intro, calibration and voyage saves use preview-only keys even though both sites share the account's github.io origin.

Later, use Run workflow again to refresh the preview from the latest redesign branch. Source changes alone do not automatically publish the live game. Real iPhone Safari performance still needs your playtest; existing local checks used Chromium mobile emulation.
